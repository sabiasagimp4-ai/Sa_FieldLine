# YMM4 本実装（Direct2D）の設計メモ

プロトタイプで確定した挙動を Direct2D カスタムエフェクトへ移植した結果の記録。
Sa_chromablur と同じ構成（`IVideoEffectProcessor` + `D2D1CustomShaderEffectBase`
+ fxc でビルドした `.cso` を埋め込み）を踏襲している。

移植の基準は `prototype/gpu_sim.py`。これは **GPU で書ける演算だけ**で
リファレンス（`prototype/fieldline.py`）を再現したもので、HLSL は
このファイルの式をそのまま写している。数式を変えるときはまず gpu_sim を直し、
`tests/gpu_pipeline_regression.py` で見た目が変わらないことを確かめること。

---

## 単一パスでは無理なので、パスを分ける

「広域拡散 → 場の確定 → 流線積分 → 引き伸ばしの伝播」で必要な近傍サイズが全く違う。

| パス | シェーダ | 解像度 | 入力 | 出力 |
| --- | --- | --- | --- | --- |
| P0 | `Luma` | 等倍 | 元画像 | R = 輝度 |
| P1 | `Edge` | 等倍 | σ,2σ,4σ,8σ,16σ でぼかした輝度 (5) | RG = 法線(折込), B = エッジ強度 |
| — | `Stats` | 1/2 | Edge / Spread | (x², 1) |
| P2 | `Confidence` | 等倍 | Edge, 全画面RMS | RG = conf·n(折込), B = conf |
| P3 | `Spread` | 1/2 | R/32〜R でぼかした conf·n (6) | RG = V(折込), B = φ |
| P4a | `FieldDir` | 1/2 | Spread, 全画面RMS | RG = v(折込) |
| P4b | `FieldA` | 1/2 | 平滑化した v | RG = 向き, B = 歩幅ゲート, A = curl |
| P4c | `FieldB` | 1/2 | 平滑化した v, Spread, RMS | R = amp, G = φ, B = res |
| P5 | `Radial` | 1/2 | FieldB | RG = 外向きの単位ベクトル |
| P6 | `Advect` | 等倍 | 元画像, FieldA, FieldB | 変位サンプリングした色 |
| P7a | `Priority` | 等倍 | conf | R = conf^1.2 |
| P7b | `StretchInit` | 等倍 | 変位後の色, Radial, 優先度 | RGB = 運ぶ色, A = スコア |
| P7c | `StretchStep` ×N | 等倍 | 直前のパス, Radial | 同上（1 歩ぶん伝播） |
| P7d | `Composite` | 等倍 | 変位後の色, 伝播結果 | 不透明で上書き |
| P8 | `Post` | 等倍 | 合成色, FieldA, FieldB, 元画像 | 発光 / 力線 / 元画像を残す |

長距離拡散を縮小した解像度でやるので、**`Radius` を上げてもコストがほとんど増えない**。

解像度は下げすぎると眠くなる。3 倍に拡大して比べた結果:

| | 1/4 | 1/2 | 等倍 |
| --- | --- | --- | --- |
| 場 | 曲がりを上げた時の細部が溶ける | ほぼリファレンス通り | ごくわずかに勝る |
| 引き伸ばしの伝播 | 論外 | 帯の境界も運ぶ色も眠い | リファレンス通り |

場は **1/2**、伝播は **等倍**にした。伝播を 1/2 にすると 1 パスのコストは 1/4 だが、
運ぶ色そのものが半分の解像度になるので、帯の中のディテールが戻らない。

## リファレンスから変えた所と、その理由

### 1. percentile 正規化 → 全画面 RMS

リファレンスは `np.percentile(|x|, 99)` で正規化している。GPU では並べ替えができない。

代わりに **`(x², 1)` を出すパスを作り、`Scale(0.5)` を 1x1 になるまで重ねて**
全画面平均を求め、`sqrt` を取って RMS にする。`Scale(0.5)` の線形補間は
ちょうど 2x2 の箱平均になるので、これは厳密な平均。

1x1 の結果は `Border(Clamp)` で無限に広げるので、どの位置で読んでも同じ定数が返る。
読む側は座標を気にしなくてよく、CPU への読み戻し（＝同期待ち）も要らない。

percentile と RMS の比は `K_MAG` 等の定数で吸収する。値は
`prototype/gpu_sim.py` の頭と `Shaders/FieldLineCommon.hlsli` の両方にあり、
**必ず一致させること**。

> **局所ぼかしで正規化してはいけない。** 一度 `blur(x², 大きいσ)` で試したが、
> 平坦な領域ほど分母が小さくなり、そこだけ効果が最大になる。
> 結果は画面全体が均等にぐにゃぐにゃ歪む、まさに避けたかった絵になった。

### 2. 符号つきの値は [0,1] に折り込む

法線・ベクトル場・curl は負になる。中間バッファが 8bit しか取れない環境だと
潰れて場が壊れるので、`SA_ENC2/4/6` で `[0,1]` に折り込んで持つ。

アフィン変換なので、**重み和 1 の平均（ガウスぼかし・箱平均）を通しても壊れない**。
折り込んだまま拡散させ、使う直前に復号できる。

あわせて `D2D1_PROPERTY_PRECISION`（= `0x80000007`）に 16bit float を要求している。
効けばフル画質、効かなくても折り込みのおかげで破綻はしない。

### 3. 引き伸ばしの伝播は歩幅が命

**1 画素ずつ長い流線を追ってはいけない。** 鞍点の近くで隣接画素の流線が
指数的に離れ、出力が櫛状の破線になる。解像度を上げても消えない
（画素のエイリアスではなく実構造のため）。

毎パス 1 歩上流だけを見て受け継ぐ形にすると、バイリニア補間が発散を抑えるので縞が出ない。
ただし **1 歩が大きいと縞が戻る**。プロトタイプでの実測:

| 1 歩 | 縞 |
| --- | --- |
| 0.9px / 1.5px | 出ない |
| 2px | わずかに出る |
| 3px 以上 | はっきり出る |

`flow_length=140` なら 93 パス。解像度を落とせば 1 パスは安くなるが、
運ぶ色の解像度も落ちるので帯の中身が眠くなる。**等倍・1 歩 1.5px** にした。

必要なパス数は `流線の長さ ÷ 1.5px`。UI の **ステップ数**（既定 192）がこれを上限で抑えるので、
長い流線では上げる必要がある。足りないと 1 歩が粗くなって縞が戻る。

### 4. スコア 1 本で距離も兼ねる

リファレンスは「輪郭の強さ」と「伝播距離」を別々に運び、
`強さ - tie*距離` で比較している。RGBA では色で 3 本使うので 1 本しか残らない。

`score = 強さ - tie*距離` をそのまま A に入れれば比較には足りる。
1 歩ぶんのペナルティは定数（`0.03 / パス数`）なので、
上流の score から引くだけでよい。到達距離の上限はパス数そのものが担保する。

塗る／塗らないの閾値は score に距離ぶんが入っている分だけ下げて補正する（`gate - 0.015`）。

### 5. 力線（LIC）の正規化と粒

リファレンスは LIC のあと σ=14 のぼかし 2 枚で局所コントラスト正規化している。
等倍で 2 パス増えるので、**標準偏差を解析的に出して割る**形に置き換えた。

流線に沿って平均される有効本数はおよそ「経路長 / ノイズの粒」なので、
`std ≈ 0.5 * sqrt(粒 / 経路長)`。

ノイズは白色ノイズのぼかしではなく値ノイズ（ハッシュ + smoothstep 補間）で、
**シーン座標に固定**している。スクリーン座標だと素材が動いた時に線が泳ぐ。

リファレンスは LIC のあとにアンシャープも掛けている。等倍でぼかしを増やしたくないので、
代わりに**ノイズの格子を細かく**した（セル = 粒。当初は粒×2 にしていて、線が太く眠かった）。
LIC は線に沿って平均する操作なので、格子を細かくすると線を横切る向きのコントラストが上がる。

### 6. 色空間

Sa_chromablur と同じく、**入力の格納値のまま**扱う（sRGB↔リニア変換を挟まない）。
引き伸ばしは平均ではなく保持なので、色空間の違いはほぼ出ない。

### 7. アルファ

色はプリマルチプライのまま運ぶ。引き伸ばしが届いた画素は
**アルファを 1 にして上から被せる**（元のフレームと合成しない）。
不透明素材では何も変わらず、切り抜き素材では輪郭の色が外へ張り出す。

## D2D を組む上での注意

- **ぼかしは `Border(Clamp)` → `GaussianBlur(Hard)` → `Crop`** で挟む。
  そのまま掛けると画面外が透明扱いになり、フレーム縁に偽のエッジが立つ。
  `Crop` を入れるのは、矩形を毎パス確定させて座標の対応を保つため。
- **`Scale` は中心 (0,0)** に固定する。シーン座標 `p` のテクスチャ上の位置が
  `p * 倍率` になるので、等倍のシェーダから `p * 0.25` で場を読める。
- **`MapOutputRectToInputRects` は必要な分だけ要求する。**
  全部要求すると、タイル分割された時に上流を何度も描き直す羽目になる。
  解像度の違う入力と、流線が遠くまで走る入力（元画像）だけ全体を要求する。
  どの入力を全体要求するかは定数 `c5.w` のビットマスクで渡している。
- **定数バッファは明示的な `cbuffer`** にする。ばらの global 変数だと、
  使っていない定数が最適化で落ちた時に並びがずれる可能性がある。
- **D2D のサンプリングヘルパを自前の関数の中で呼ばない。**
  エントリポイントのローカル（走査座標）に展開されうるので、
  流線をたどる部分はマクロで書いている（`Post.hlsl` / `FieldB.hlsl`）。
- **`StretchStep` はパス数ぶんインスタンスを作る**（遅延生成、上限 256）。
  必要な数だけ `Composite` に繋ぎ、余りは参照されないので描画もされない。

## 未確認の点

Windows と YMM4 が要るのでこの環境では確かめられていない。最初のビルドで見る所:

1. `Vortice.Direct2D1.Effects` の `Border` / `GaussianBlur` / `Scale` / `Crop`
   のクラス名とコンストラクタ。プロパティはインデックス（`d2d1effects.h` の値）で
   設定しているので、名前が変わっていても影響しない。
2. `D2D1CustomShaderEffectBase.SetValue` に標準プロパティのインデックス
   （負の値）を渡せるか。渡せない場合は try/catch で無視され、
   精度は上流の組み込みエフェクトから継承される。
3. 多入力（`[CustomEffect(5)]` / `(6)`）の登録。
4. 長い `StretchStep` の連鎖で中間バッファがどれだけ積まれるか。
   等倍 RGBA16F を 93 枚ぶん同時に持つと 1.5GB になるので、
   D2D が中間を使い回さない場合はここが効く。その時は `FieldLineProcessor` に
   伝播用の `Scale(0.5)` を戻して 1/2 にする（眠くなるが 1 パスが 1/4 になる）。

## 動画にするときの注意

- ノイズはシーン座標固定（上記）
- 場は素材の内容だけで決まるので、素材が静止していればフレーム間でちらつかない
- `曲がり` を上げると特異点（渦の中心）が現れる。素材が動くと特異点が動いて目立つので、
  動画では `滑らかさ` をやや高め（50% 前後）にするのが安全
- 引き伸ばしの境界は二値なので、フレーム間でちらつく可能性がある。
  気になる場合は `引き伸ばし閾値` を下げて境界を輪郭から遠ざける
